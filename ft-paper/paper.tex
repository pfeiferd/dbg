    \subsection{Approach}
    \label{approach}
Figure \ref{ftsketch} captures our approach with regard to a simplistic $k$-mer database 
with $k = 2$:
\begin{enumerate}
	\item Species $X$, $Y$, $Z$ under a common genus $W$ have respective sequences associated. 
	\item After filling the database, the $2$-mers are assigned to their species. The figure simplifies the state of the database after this step.
	\item The lowest common ancestor update (LCA update) pushes the $2$-mer \texttt{CT} up to $W$ because it occurs in the sequence of both $X$ and $Y$. However, it does not occur in $Z$. So, according to this database a read \texttt{CT} would just be classified as $W$ although $Z$ is not even a candidate species for \texttt{CT}.
	\item Genestrip-FT's refinement adds an artificial node $h$ to the taxonomy with $X$ and $Y$ as children but not $Z$. Also, the refinement \emph{pushes down} \texttt{CT} from $W$ to $h$. According to this refined database, a read \texttt{CT} would be classified as $h$ and so, $Z$ is excluded as candidate species for \texttt{CT}.
\end{enumerate}
 So in general, this type refinement potentially improves classification precision: E.g., if a read was classified under a genus taxon in a non-refined database, then \emph{the corresponding refined database may allow for narrowing down the candidate species to less species than originally listed under that genus}.

\subsection{Database Refinement}
\label{dbrefinement}
   
We explain the system's refinement procedure by means of a small and initially unrefined example database including three species under the genus Orthopoxvirus. The structure of the unrefined database is shown in Figure \ref{simplelcadb}. For sake of simplicity, we restrict the refinement to the rank genus only, although \emph{it is normally performed simultaneously on all levels of the database's taxonomy} but its leaves.

Genestrip structures the complex computation of a $k$-mer database via goals as explained in \cite{genestrip-pub}. The goals form a dependency graph where a goal $g_1$ is executed only if its computational result is needed by a dependent goal $g_2$, and if $g_1$'s result has not been computed yet. Genestrip FT is implemented as an extension of the original goal graph formed by Genestrip. Figure \ref{ftgoals} presents an extract of the additional goals, with most of Genestrip's original goals omitted. 

  \begin{figure}[h]%
        \centering        
\includegraphics[width=8cm]{figs/ft-goals-extract.pdf}
         \caption{Extract of additional goals required by Genestrip FT for the refinement of a corresponding $k$-mer database. The file goal \texttt{ftdb}, prefixed with \texttt{f:} stores the refined database as a file and depends on several, so-called object goals prefixed with \texttt{o:}. Genestrip FT's goals also depend on some of Genestrip's original goals with the latter depicted at the top in dashed boxes. An extract of Genestrip's original goals can be found in the Appendix of \cite{genestrip-pub}. The different types dependencies and goals (such as object goals or file goals) are explained there too.}\label{ftgoals}
    \end{figure}   

In the following, we briefly explain the essential goals needed for the computation of a refined database:
\begin{enumerate}
	\item \verb|kmerindexbloom| associates each $k$-mer stored on the genus rank with the original species taxon of the sequence in which it occurred. To achieve this, the original sequences that were used to generate the unrefined database must all be reread. The mapping of a $k$-mer to its original species taxon is hashed; the resulting hash code is stored via a Bloom filter \cite{bloomfilter} in order to save main memory.\footnote{A Bloom filter is a probabilistic data structure for an efficient and compressed storing of values but also for a fast lookup of entered values. However this comes at the expense of a configurable, usually low false positive rate at lookup time. Bloom filters and  probabilistic filters in general \cite{10.1145/2674005.2674994,9920402,10.1145/3510449,10.1145/3376122} are widely used in the context of metagenomics tools \cite{biobloom, Piro:2020aa, 10.1093/nargab/lqaf094}.}
	
	\item \verb|intersectcount| computes the number of common $k$-mers $c(t_1, t_2)$ between any two species taxons $t_1$ and $t_2$ under the same genus. To do so, it consults the Bloom filter produced via the goal \verb|kmerindexbloom|. Based on $c(t_1, t_2)$, it also determines the Jaccard index $J(t_1, t_2) =  c(t_1, t_2) / (c(t_1, t_1) + c(t_2, t_2) - c(t_1, t_2))$ \cite{jaccard} as a similarity measure of the two sets of $k$-mers belonging to $t_1$ and $t_2$ on the genus, respectively. Regarding our running example, Table \ref{intersectioncounts} shows the raw intersection counts whereas Table \ref{jaccard} states the resulting Jaccard indices. For simplicity, we skip the background of the column \enquote{OTHER} for now --- it will be explained at the end of this section.

	\item The goal \verb|dendrogram| from Figure \ref{ftgoals} computes a dendrogram using the standard agglomerative clustering algorithm \enquote{HAC} \cite{King01031967,1394399}, where the cluster distance is based on the Jaccard index $J$ from \verb|intersectcount|. Since the taxonomic refinement is governed by the aim of improving classification precision (see Section \ref{approach}), we chose \enquote{Single Linkage} \cite{King01031967} as the default linkage strategy. This linkage strategy is suitable because it merges clusters on the basis of their most similar $k$-mer sets they contain. Nevertheless, other linkage strategies such as UPGMA and WPGMA \cite{Sokal1958ASM} may be configured instead. Figure \ref{dendrogram} depicts the resulting dendrogram as computed on the basis of Table \ref{jaccard}.

	\item The goal \verb|updatestore| reorganizes the database's taxonomy tree by adding new tree nodes under a genus as induced by the previous goal's dendrogram. Furthermore, $k$-mers are pushed down, i.e. reassigned, to the newly added nodes accordingly. Hereby, each $k$-mer is pushed down as far to a new node $n$, such that all species with sequences containing that $k$-mer still remain descendants of $n$.

	\item Finally, \verb|ftdb| stores the refined databases as a file.
\end{enumerate} 

	Figure \ref{simplerefdb} depicts the refined taxonomy for the Orthopoxvirus example and also states the number of $k$-mers as stored per node in the refined database. As can be seen, about 56 \% of the $k$-mers that originally resided on the genus Orthopoxvirus got pushed down to the newly added nodes (see Figure \ref{simplelcadb} for comparison). The new nodes obtain an artificial taxon prefixed with \enquote{000} to distinguish them from regular taxonomic entries, and their artificial rank is set to \enquote{REFINED}.

Lastly, we motivate the need for the column \enquote{OTHER} in Tables \ref{intersectioncounts} and \ref{jaccard} but also for respective nodes in Figure \ref{simplerefdb}: Genestrip's LCA update is generally based on more taxons and associated sequences than just the ones stored in a resulting database \cite{genestrip-pub}. Typically, \emph{all} taxons and associated sequences under a RefSeq category are considered during the LCA update, if the database comprises any taxon from that category. However, this means that a $k$-mer $a$ may end up on a rank above species even though the corresponding database contains just single species-level taxon $t$ associated with a sequence containing $a$. For such cases \enquote{OTHER} acts as placeholder for taxons that are not in the database but caused $a$ to be pushed to a higher rank. Otherwise, if that placeholder was missing during the refinement, $a$ would inevitably be pushed down too far towards $t$ via the goal \verb|updatestore| from above. Figure \ref{ftother} further details this issue by means of a small example.

\subsection{Intrinsic quality measures for database refinement}
\label{intrinsicqms}    
    In this section, we consider quality measures regarding database refinement irrespective of read analysis and read classification results. For this purpose, we establish \emph{path precision and path recall} for a $k$-mer database $d$ that has a taxonomy tree associated and where stored $k$-mers have taxons, i.e. nodes, assigned from that tree. Below, in the result section, we use these new measures amongst established measures to assess refinement quality. 
    
    Let $t$ be a \emph{data taxon}, i.e., \emph{a taxon with a complete genome directly associated whereby at least one $k$-mer from that complete genome is also stored in $d$}. For example in RefSeq, complete genomic sequences are often associated with taxons of the rank species or below -- such taxons therefore constitute data taxons.
    
    Based on the following counts, the quality of the taxonomic refinement can be assessed per data taxon $t$ in $d$:
\begin{description}
    \item \textbf{Positive counts $P$ per data taxon $t$ in database $d$:} The number of unique $k$-mers in $d$ that occur in the genome associated with $t$.

    \item \textbf{True positive counts $TP$ per data taxon $t$ in database $d$:} The number of unique $k$-mers in $d$ that occur in the genome associated with $t$ where in $d$, such $k$-mers are associated with some taxon on the path from $t$ to the taxonomic root including $t$ itself.
    
    \item \textbf{True positive plus false positive counts $TP + FP$ per data taxon $t$ in database $d$:} The number of unique $k$-mers in $d$ assigned to any taxon on the path from $t$ to the taxonomic root including $t$ itself.
\end{description}
    
   These counts allow for defining \emph{path precision} as $TP / (TP + FP)$ and \emph{path recall} as $TP / P$.
   
   As an example, consider Figure \ref{ftsketch} from above: In (3), the path precision of $Z$ is $2/3$ because there are three $2$-mers on the path from $Z$ to the root $W$ but one of them, \texttt{CT}, is not in $W$'s sequence. In (3), $X$ and $Y$ both have a path precision of $1$. The refined database in (4) has a precision of 1 for $X$, $Y$ \emph{and} $Z$. Path recall is $1$ for all of the cases in (3) and (4). 
        
For fair a assessment of precision, we require that each data taxon must be a leaf node in the taxonomy tree of database $d$. This can be easily be enforced by a tree transformation explained via (3) and (4) in Figure \ref{fttrans}. If the requirement was not met, then two data taxons on the same path would likely result in an inadequately lowered path precision (as in Figure \ref{fttrans} (1) and (2)). Note that the described transformation leaves the phylogenetic structure of a given taxonomy intact.
Figure \ref{simplerefdbtrans} exemplifies the transformation when integrated into the refinement of the database from Figure \ref{simplelcadb}.\footnote{When carefully comparing the $k$-mer counts of similar nodes from Figure \ref{simplerefdb} and \ref{simplerefdbtrans}, one finds minor differences such as for \enquote{10245/OTHER}. Note, that these differences originate in the use of a probabilistic data structure, i.e. a Bloom filter, during the refinement procedure according to Section \ref{dbrefinement}.}

In particular, we report averages over all taxons under the same species or the same genus, respectively.     Note that for a taxonomy tree with a branching factor $\geq 2$ (which is the standard case) a high average path precision ensures the a $k$-mer $a$ in $d$ is located as closely as possible above a data taxon or right at data taxon whose genome(s) contain $a$. Otherwise, if $a$ was located higher up in the taxonomy, then $a$ would also be on the path to the root starting from a data taxon $s$ whose genome does not contain $a$. But this would increase the $FP$-count of $s$ and in turn would lower the average path precision.
    
    Likewise, a high average path recall ensures that a $k$-mer $h$ in $d$ is assigned to a tree node such that \emph{as many data taxons as possible} which contain $h$ in their genome are subordinate or equal to that node. Otherwise, the $k$-mer $h$ would not be on the path to the root for such a taxon. But this would decrease the $TP$-count of that taxon and in turn lower the average path recall.
    
    So together, both, a high average path precision and a high average path recall suggest that $k$-mers are located at a near optimal position in the taxonomy tree -- not too high up to lower precision and not too far down to lower recall.

\subsection{Phylogenic Mapping}

Genestrip FT's database refinement lends itself for a comprehensive visualization of even large phylogeny trees with evolutionary distances being integrated. Resulting tree representations refine the existing NCBI taxonomy \cite{taxonomy} and derive from a refined $k$-mer database. Here, we briefly discuss computational aspects for embedding the evolutionary distance in such trees.

   \subsubsection{The evolutionary distance $d$}
    
We briefly introduce an approximation of the evolutionary distance $d$ as a ratio of mutations of genomes or sequences, respectively. The approximation has been derived before in \cite{skmer} where it is expressed via the Jaccard index over shared $k$-mers between genomes. Besides, \cite{Ondov:2016aa} pointed out a similar approximation. For clarity of discussion, we also derive $d$, but express it in terms of counts available in a Genestrip database and related taxonomy trees. Afterwards, we build on these considerations to adequately integrate $d$ into depicted, refined trees such as produced via Genestrip-FT. 
    
The following assumptions are essentially the same as in \cite{skmer} and \cite{Ondov:2016aa}:
    Let $|s|$ be the length of a sequence $s$ transformed to a sequence $s'$ via mutations of bases. We assume that $|s| = |s'|$ and consider the number of observable mutations $m$, i.e. all base positions $1 \leq i \leq |s|$ where $s(i) \neq s'(i)$. We also assume that these mutations are uniformly distributed over $s'$.
    Let $X$ be a random variable for the number of differing $k$-mers between $s$ and $s'$ depending on the $m$ mutations. For simplicity we assume that there are no duplicate $k$-mers in either $s$ or $s'$ so that $X$ is also the number of differing \emph{unique} $k$-mers. As our last simplification, we consider observations of $k$-mers within $s$ and analogously within $s'$ to be mutually independent. 

    A mutation occurs at a chance of $m/|s|$. So the probability for a changed $k$-mer, which must contain a least on mutation, is $p(m) = 1 - (1 - m/|s|)^k$. Since the number of $k$-mers in $s$ and $s'$ is $|s|-k+1$, $X$ follows the binomial distribution $X \sim B(|s|-k+1, p(m))$.         
    In our context, \emph{we measure the number $E$ of unique $k$-mers differing between $s$ and $s'$ but we want to estimate the distance $d:=m/|s|$ as a ratio of mutations over the sequence $s$}. We therefore approximate $E \approx E[X] = (|s|-k+1) \cdot p(m)$ and solve by $d$:
 \begin{equation}
d \approx 1 - \sqrt[k]{1 - E / (|s| - k + 1)} \approx 1 - \sqrt[k]{1 - E / |s|} =: d(E/|s|)\label{distanceapprox} 	
 \end{equation} 
Figure \ref{nfunc} shows a plot of the function $d(E/|s|)$: It starts with a slope of $1/(k-1)$ because when $n$ is small, every mutation results in about $k-1$ different $k$-mers. The estimate $d(E/|s|)$ becomes very sensitive, i.e. less reliable, when $E$ reaches $|s|$. For practical considerations, we therefore indicate it in taxonomy trees, when $d$ exceeds a configurable threshold $t_d$.

\subsubsection{Embedding of $d$ in taxonomy trees}

We want to apply $d$ to a node $n$ in the context of a taxonomy tree such as in Figure \ref{simplerefdb}. More precisely, we estimate $d_n$ to be the maximum evolutionary distance \emph{from $n$'s parent to the data taxons\footnote{See Section for \ref{intrinsicqms} for the definition of the term \enquote{data taxon}.} under $n$}:
\begin{itemize}
\item
For that, $above(n)$ shall sum over the $k$-mers assigned to nodes above $n$ towards the tree's root excluding $n$. 
\item 
Regarding $below(n)$, we consider each path starting from $n$ to any leaf node under $n$ including $n$ itself. We sum over the $k$-mers assigned to all nodes along each path and set $below(n)$ to be the maximum sum from such paths. $p_n$ denotes some path leading to the maximum sum of $below(n)$. 
\end{itemize}
We set $d_n := d(E_n/|s_n|)$ by letting $E_n := below(n)$ and $|s_n| := above(n) + below(n)$.
This way, $d_n$ measures the evolutionary distance from $n$'s parent to the leaf of $p_n$. 
Since we use the maximum sum in $below(n)$, this estimate is conservative for $n$.
However, to depict evolutionary distances in a given taxonomy tree we must represent the portion $dp_n$ of $d_n$ relating to the branch from a node $n$'s parent to $n$ itself.
Let $c$ be the child of $n$ on the path $p_n$. We have $d_n \geq d_c$ because $E_n = below(n) \geq E_c = below(c)$, $|s_n| \geq |s_c|$ and because $d$ is monotonically increasing. So, to estimate the desired portion, we simply set $dp_n := d_n - d_{c}\geq 0$.

Figure \ref{simplerefdbdist} depicts a resulting taxonomy tree for the same database as in Figure \ref{simplerefdb} but with horizontal line lengths encoding distance portions.\footnote{We set the horizontal line length of a node $n$ to a minimum when $d_n = 1$ although $dp_n$ might be large. This is because the resulting distance portion is too unreliable and tends to cause a large but non-informative indentation in the tree. In Figure \ref{simplerefdbdist}, this exception affects for the node \enquote{Viruses (10239) acellular root} only.}
