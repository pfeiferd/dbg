\section{Genestrip's goal graph}
\label{ggg}

    Figure \ref{goalgraph} depicts an extract of Genestrip's goal dependency graph: Several goals (prefixed with \verb|d:|) revolve around automatically downloading all necessary files of the RefSeq, Genbank and other data from the NCBI's Web site \citep{Sayers:2025aa}.
    When required for database generation, the goal \verb|refseqfna| downloads the RefSeq genomes belonging to a matching category as a collection of zip files. The collection is one of NCBI's  standard offerings. By consulting the goal \verb|checksummap|, \verb|refseqfna| also performs an MD5 fingerprint check after each zip file download to ensure data integrity and reattempts the download in case the initial file appears to be corrupted.

    Several object goals (prefixed with \verb|o:|) load files and create data structures or compute results in main memory for further processing. Most file goals (prefixed with \verb|f:|) write computational results to files.
    Boxes with edged corners depict goals that are meant to be executed directly via the command line. For example,
    the goal \verb|match| is for fastq file analysis but it would trigger a respective database generation goal if the corresponding database file was missing.

    Solid edges symbolize ``eager" dependencies where the existence of a dependency's result is ensured prior to the execution of the dependent goal. In contrast, dotted edges symbolize ``lazy" dependencies where the existence of a dependency's result is ensured when first accessed during the execution of the dependent goal.

        Besides $k$-mer matching and read classification, Genestrip supports filtering of fastq files via a Bloom filter in similarity to \citep{biobloom}. When generated via the goal \verb|index|, the Bloom filter gets stored in a separate file. The goal \verb|filter| loads the filter and processes fastq files accordingly. The standard configuration of the filtering process rewrites a read to the output if the read contains at least one $k$-mer that is recognized by the filter since because of this, the read may belong to a selected organism of interest.

\section{Bloom filter hashes}
\label{blhashes}

 A Bloom filter is a probabilistic data structure to efficiently test whether or not a data object got stored \citep{bloomfilter}. It generally depends on $n$  hash functions $h_1, \ldots, h_n$ that ideally should be statistically independent from each other. In our case, the input to each hash function is a $k$-mer encoded as a long value $l$ and its output is an index of a bit in a large bit vector $b$ which forms the Bloom filter's store. When the value $l$ gets stored, the bits $b[h_1(l)],\ldots,b[h_n(l)]$ are set but any other bits in $b$ remain untouched. To test whether $l$ is contained in the filter, one simply checks whether $b[h_1(l)] \wedge \ldots \wedge b[h_n(l)]$ is true. False positives from this check may occur since the storing of values other than $l$ may have caused the corresponding bits to be set. If the number of data objects to be stored is known, then the false positive rate can be optimized via $n$ and the size of $b$, but this also demands the independence of the $h_i$ \citep{bloomfilter}.
    
    A typical challenge is to determine a method that generates an arbitrary number of $h_i$ which is needed since $n$ may vary: On the one hand, the computation of $h_i(l)$ should be very efficient but also, the Bloom filter's false positive rate must not suffer too much, if true independence cannot be guaranteed for the $h_i$. Regarding the storing of $k$-mers we found that the simple generator method
    \[h_i(l) = ((l \oplus s_i)\mod |b|) + 1\] 
    works well in practice. Hereby, $\oplus$ is the bitwise xor-operator, $s_1, \ldots, s_n$ are randomly initialized long-valued salts and $|b|$ is the size of $b$. Functional testing showed that for uniformly distributed $k$-mers, this method indeed keeps the false positive rate close to its theoretical expectation. Note that the operator $\mod$ from above may be replaced by any other efficient mapping operator that fairly maps to the interval $0 \ldots |b| - 1$.

    \section{The dust function $d$}\label{dustfunction}
We designed a simple dust function $d(s)$ that allows for recognizing and potentially excluding highly repetitive $k$-mers $s$ based on the following rationale:
\begin{enumerate}
	\item Simple repeats like \texttt{TTTTTT}, repeating pairs like \texttt{ATATAT} and repeating triplets like \texttt{ATCATC} should be recognized. (Triplets also form the basis of the approach in \cite{doi:10.1089/cmb.2006.13.1028}.)
	\item The function should be based on the number of times a single base, a pair or a triplet is repeated. E.g. \texttt{AT} is repeated twice in \texttt{ATATAT} and \texttt{ATC} is repeated once in \texttt{ATCATC}. 
	\item A repeat's contribution to $d$ should grow more than linearly with the repeat's length. E.g., \texttt{AAAACA} should obtain at least the $d$-value of \texttt{AACAAA} (or more). 
	\item $d$ should be symmetrical. This is because a $k$-mer and its reverse complement should obtain the same dust value \citep{doi:10.1089/cmb.2006.13.1028}.
	\item $d(s)$ should be computable in $O(|s|)$ and should lend itself for streaming computation. I.e., if $d(s) = d(s_1 \ldots s_k)$ is known, then $d(s') = d(s_2 \ldots s_k s'_{k+1})$ should be computable in constant time.
\end{enumerate}

To specify the dust function $d$, we first define the \emph{skip-$c$-repeat length} at position $i$ in a string $s$ where  $1 \leq i \leq |s|$ and $c \geq 0$:    
\[srl_c(s, i) = \max \{ r\ |\ i + r - 1 \leq |s| - c - 1 \wedge \bigwedge_{j = i}^{i + r - 1} s_j = s_{j + c + 1} \}\]
E.g., two skip-$1$-repeat lenghts for $s = \texttt{ACTCT}$ are $srl_1(s, 0) = 0$ and $srl_1(s, 1) = 2$.

We then determine the \emph{next position} $np_c(s,l)$ of the $l$-th skip-$c$-repeat length in $s$ with $|s| \geq 1$ as follows: 
\[
    np_c(s, l) = \begin{cases}
        1 & \text{for } l = 1\\
        np_c(s, l - 1) + srl_c(s, np_c(s, l - 1)) + 1 & \text{for } l > 1, np_c(s, l - 1)  < |s|
        \end{cases}
  \]
E.g. for $s = \texttt{ACACTC}$ we get $np_1(s, 1) = 1$ and $np_1(s, 2) = 4$.
For clearer discussion, we declare a \emph{skip-$c$-repeat} to be a substring of $s$ of length $srl_c(s,i)$ at a position $i$ \emph{as provided by $np_c$} (but not at any other positions).

%\[sr_c(s,i) = srl_c(s, i)\ / (c + 1)\]
%%E.g., since $srl_1(\texttt{ACTCT}, 1) = 2$, \texttt{CT} is repeated once at position 1, i.e. $sr_1(\texttt{ACTCT}, 1) = 1$.


%Let $F(h)$ be the factors of an integer $h$. 
The dust function $d(s)$ sums over the lengths of all skip-$c$-repeats in $s$ with $c = 0,\ldots, c_{\max}$ transformed via a variant of the Fibonacci function \citep{oeisA000045} where $fib(0) = 0, fib(1) = 1, fib(2) = 2$ and $fib(n) = fib(n - 1) + fib(n - 2)$ for $n > 2$:
\[d(s) = \sum_{c = 0}^{c_{\max}}  \sum_{l=1}^{np_c(s, l) \leq |s|} fib(srl_c(s,  np_c(s, l))) \]
The use of the Fibonacci function in $d$ accounts for point 3 from the above rationale.

 $d(s)$ is symmetrical: Let $s'=s_k \ldots s_1$ be the reverse of $s=s_1\ldots s_k$; then it follows from the definition of $srl_c$ that for a skip-$c$-repeat at position $i$ there is $srl_c(s, i) = srl_c(s', |s| - i - srl_c(s, i) + 1)$. Since $np_c(s, l)$ determines the positions of all skip-$c$-repeats, doing so in reverse order leads to the same skip-$c$-repeat lengths and so, $d(s) = d(s')$.

%We don't use $sr$ but $srl$ in $d$ because otherwise, repeats with a larger $c$ would become underrepresented at higher values of $d$. E.g., for a $31$-mer the maximum skip-$2$-repeat is 9 but the maximum skip-$0$-repeat is 30. This means that with a threshold $t$ for $d(s)$ and $d(s) \geq t \geq fib(9)$, no true skip-$2$-repeat (which is not a skip-$0$-repeat already) would qualify anymore.
 
 $d(s)$ does not compensate for double counts, e.g. $sr_0(\texttt{AAAA}, 1) = 3$ but also $sr_1(\texttt{AAAA}, 1) = 1$. We consider this as legitimate since \texttt{AAAA} is indeed both a skip-$0$-repeat of \texttt{A} and a skip-$1$-repeat of \texttt{AA}. In the general case, given some skip-$c$-repeat $h$ and a multiple $f + 1$ of $c + 1$ with $f \leq c_{\max}$: If $|h| > f$, then $h$ is also a skip-$f$-repeat. Therefore, $h$ gets ``boosted" in $d$ via any corresponding multiple $f + 1$.
 
 For an efficient implementation that considers no more but triplets, we set $c_{\max} = 2$.
 Although the functional specification of $d(s)$ from above may seem intricate, its computation is simple and iterates just once over $s$. Listing \ref{dust_alg} presents a basic Java implementation that computes $d(s)$ for $c_{\max} = 2$.\footnote{Although the presented algorithm works just for $c_{\max} = 2$, it can obviously be generalized for a larger $c_{\max}$ by introducing appropriate loops over $c = 0,\ldots,c_{\max}$.} It confirms the desired complexity of $O(|s|)$ given that $c_{\max}$ is constant.
 With regard to Genestrip, we implemented a streaming variant as well with the qualities as described in the rationale from above (not shown).

 \begin{lstlisting}[frame=single, basicstyle=\footnotesize\ttfamily, language=Java, numbers=left, numberstyle=\tiny\color{black},caption= {Computation of $d(s)$ for $c_{\max} = 2$ in Java with a simplistic representation of a string $s$.}, ,label={dust_alg}]
    // int fib[] = ... is assumed to be defined beforehand.
    public int d(byte[] s) {
        int d = 0, srl0 = 0, srl1 = 0, srl2 = 0; // skip-c-repeat lenghts
        int l1 = -1, l2 = -1, l3 = -1;           // previous elements of s
        for (int i = 0; i < s.length; i++) {
            if (s[i] == l1) srl0++;
            else {
                d += fib[srl0];
                srl0 = 0; }
            if (s[i] == l2) srl1++;
            else {
                d += fib[srl1];
                srl1 = 0; }
            if (s[i] == l3) srl2++;
            else {
                d += fib[srl2];
                srl2 = 0; }
            l3 = l2; l2 = l1; l1 = s[i];
        }
        d += fib[srl0] + fib[srl1] + fib[srl2];
        return d;
    }
\end{lstlisting}

    \section{Mean absolute error...}
    
    In addition to the results from Figure \ref{salivascatter}, we measured the mean absolute percentage error of $k$-mer counts for all of the five human saliva fastq files from Table \ref{errorsviral} between the complete viral database and the ``human virus only" database in a variant where both databases belong to KrakenUniq and another variant where they both belong to Genestrip.

    More precisely, we used the following error measure:
    Let $S_d$ be the list of all taxa \emph{for the rank species or below} in a database $d$.
    The mean absolute percentage error $err_{f,d}(e)$ for a database $e$ with respect to fastq file $f$ and the ``ground truth" database $d$ is as follows:\footnote{The term ``$k_{t,f,d} + 1$" in the formula includes a Laplace correction to avoid a potential division by zero.}
    \begin{equation}
        err_{f,d}(e) := 100 / | S_{d} \cap S_{e} | \cdot \sum_{t \in S_{d} \cap S_{e}} |k_{t,f,d} - k_{t,f,e}| / (k_{t,f,d} + 1)
    \end{equation}
    Note that we limit the taxa to the rank species or below because, as discussed in the context of Figure \ref{viraldbscomp} and \ref{salivascatter}, we cannot expect $k$-mer counts and read counts to be close between $d$ and a corresponding smaller database $e$ for higher taxonomic ranks.
    Analogously, we also measured the error with regard to the counts of classified reads.

    As shown in Table \ref{errorscvhv}, the error rates for $k$-mer counts are zero under Genestrip, and for read counts, they are two orders of magnitude lower than those under KrakenUniq across all the examples. These findings solidify the usefulness of Genestrip's analysis results in the context of smaller databases.
